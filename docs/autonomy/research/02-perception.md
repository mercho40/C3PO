# 02 — Perception upgrade for the C3PO G1: open-vocabulary, transparent objects, grasp-ready 3D

Research date: 2026-11-02. Every claim has a URL. Where I could not find a measured number, I say so and label my estimate as an **estimate**.

Robot as it stands: Unitree G1, RealSense D435i head camera, Jetson Orin NX 16GB on JetPack 5.1.1 (L4T r35.3.1, TensorRT 8.5, Python 3.8). It runs YOLO11n COCO-80 as a TensorRT FP16 engine and sends `{label, bbox center, depth}` JSON to an LLM agent.

---

## TL;DR

1. **The glass fails for two separate reasons, and each needs its own fix.**
   - _Vocabulary._ COCO does have `wine glass` (40) and `cup` (41) ([coco.yaml](https://raw.githubusercontent.com/ultralytics/ultralytics/main/ultralytics/cfg/datasets/coco.yaml)). So the more likely cause is low recall on transparent instances, not a missing class name. Open vocabulary still matters for everything outside COCO.
   - _Depth._ The D435i is an active-IR stereo camera. On glass, the IR pattern lands on whatever is behind the glass, so the reported depth belongs to the table or wall, not the glass ([Intel support 000030012](https://intel.com/content/www/us/en/support/articles/000030012.html)). A better detector does not fix this.
2. **Always-on detector, on the Jetson:** replace YOLO11n with **YOLOE-26s-seg** (Ultralytics, Jan 2026) running as TensorRT FP16. Bake in a large household vocabulary (about 150–300 prompts). Measured accuracy is 30.8 LVIS AP for the s model, against 24.7 for n ([Ultralytics YOLOE docs](https://docs.ultralytics.com/models/yoloe/)). Its speed is reported as "close to closed-set YOLO speed". The model also returns masks, which the grasp stage needs.
3. **On-demand open-vocabulary search, off-board:** when the LLM asks for something the baked vocabulary lacks, run **SAM 3 / SAM 3.1** (text → masks; 30 ms per image on an H200) on an off-board RTX GPU ([SAM 3 paper](https://arxiv.org/html/2511.16719v2), [repo](https://github.com/facebookresearch/sam3)). Grounding DINO + SAM 2 is the fallback. A VLM (Gemini Robotics-ER 1.6 or the agent's own LLM) can verify the crop.
4. **3D for transparent objects:** replace the depth sample at the bbox center.
   - **v1, no training:** use the mask, fit the table plane with RANSAC, and intersect the ray through the mask's bottom contact point with that plane.
   - **v2:** depth completion off-board with **LingBot-Depth** (Apache-2.0; dexterous-hand glass-cup grasp success 60%→80%) ([repo](https://github.com/robbyant/lingbot-depth), [paper](https://arxiv.org/pdf/2601.17895)). The other option is the D435-specific **Camera Depth Model**, which is non-commercial only ([HF](https://huggingface.co/depth-anything/camera-depth-model-d435)).
5. **JetPack:** step 1 does **not** require an upgrade, because Ultralytics 8.4.198 still supports Python ≥3.8 ([PyPI](https://pypi.org/pypi/ultralytics/json)). Upgrade to **JetPack 6.2.x** once you want onboard ViT models, Super mode (+16–25% on ViTs) or Isaac ROS 3.2. There is a G1-specific JP 6.2 flashing guide in NVIDIA's GR00T-WholeBodyControl repo ([guide](https://github.com/NVlabs/GR00T-WholeBodyControl/blob/main/docs/source/references/jetpack6.md)). Flash it to a **second NVMe SSD** so the current disk, including other teams' files, stays untouched. JetPack 7.2 now supports Orin ([archive](https://developer.nvidia.com/embedded/jetpack-archive)), but I found no G1-specific image for it.

### 1.2 What this means for this robot

- **YOLOE-26 is the natural successor to YOLO11n.** It uses the same Ultralytics API and the same export flow. It adds text prompts, visual prompts and a 4,585-class prompt-free mode, and the `-seg` checkpoints return masks.
  - **Main limitation:** a TRT engine has a fixed vocabulary. In the docs' words, "a loaded export cannot accept new prompts" ([docs](https://docs.ultralytics.com/models/yoloe/)).
  - **Workaround:** bake in a large vocabulary. The docs measured, on CPU, a forward pass about 19% slower going from 80 to 1,203 classes ([docs](https://docs.ultralytics.com/models/yoloe/)), so a few hundred classes costs little. Send anything outside that vocabulary to the on-demand tier.
- **Grounding DINO and SAM 2 onboard run at about 7 FPS on Orin NX even with Super mode** ([NVIDIA](https://developer.nvidia.com/blog/nvidia-jetpack-6-2-brings-super-mode-to-nvidia-jetson-orin-nano-and-jetson-orin-nx-modules)). Running both one after the other would be about 3–4 FPS (**estimate**) and would compete with everything else on the GPU. That is acceptable for a one-shot "find the glass" request, but not for an always-on detector.
- **SAM 3 is the best "find X" model**, since a single model goes from text to masks for every instance. It is too heavy for Orin NX (about 1 s per frame with TRT, per a community build), so run it off-board.
- **Cloud detectors (DINO-X, Grounding DINO 1.6 Pro, Gemini Robotics-ER)** give the best accuracy on long-tail objects, at the cost of network latency. They suit a "verify / find rare object" tool call.

## 3. Transparent objects: detection and depth

### 3.1 Why the D435i fails

- **Active IR stereo sees through glass.** The D4xx cameras match IR stereo images with a projected dot pattern. On transparent surfaces the pattern hits the opaque surface behind, so the camera reports that depth ([Intel](https://intel.com/content/www/us/en/support/articles/000030012.html)).
- **The literature agrees.** Reflection and refraction break commodity depth sensors on transparent objects, which is why depth-based grasping fails on them ([TransCG](https://arxiv.org/abs/2202.08471v2)).
- **What the current pipeline does:** a "depth at bbox center" sample on a glass returns the table or wall behind it, or a hole (0).

### 3.2 Options, cheapest first

1. **Geometric fix, no ML (recommended v1).**
   - Take the object mask.
   - Fit the support plane with RANSAC on valid depth in a ring _around_ the mask.
   - Cast the ray through the mask's lowest pixels and intersect it with the plane. That gives the 3D contact point.
   - Cast the ray through the mask's top edge and intersect it with the vertical plane through the contact point. That gives the height.
   - The result is a 3D centroid and height that are good enough for a reach-and-grasp approach. This is my design, built from standard geometry; I found no single paper to cite for it. It needs no new models and works on JP5 today.
2. **RGB-D depth completion models** (input: RGB + raw D435 depth; output: dense metric depth):
   - **LingBot-Depth** (Robbyant/Ant Group, Jan 2026, ECCV'26). ViT-L, **Apache-2.0**. Trained on about 2–3M RGB-D pairs from RealSense, Orbbec and Kinect. Reported dexterous-hand grasp success went from 60%→80% on a glass cup and 0%→50% on a transparent box ([repo](https://github.com/robbyant/lingbot-depth), [paper](https://arxiv.org/pdf/2601.17895), [press](https://www.businesswire.com/news/home/20260126215468/en/Ant-Group-Subsidiary-Robbyant-Unveils-Spatial-Perception-AI-Model-LingBot-Depth)). No Jetson numbers are published. Run it off-board.
   - **Camera Depth Models (CDM)**, "Manipulation as in Simulation", ICLR'26. Per-camera models, **including a D435 checkpoint**, built on DINOv2 + Depth Anything V2. Explicitly targets holes from transparency. **CC-BY-NC-4.0** ([paper](https://arxiv.org/abs/2509.02530), [HF D435](https://huggingface.co/depth-anything/camera-depth-model-d435)). Fine for a school project; not for commercial use.
   - **Classic:** ClearGrasp and TransCG/DFNet. TransCG is 57,715 RGB-D images of 51 transparent objects ([repo](https://github.com/Galaxies99/TransCG)). These are older and superseded by the two above.
3. **Learned stereo on the D435i's own IR pair** (left/right IR streams):
   - **FoundationStereo** has been tested on RealSense D4xx IR pairs and "works well too" ([repo](https://github.com/NVlabs/FoundationStereo)).
   - Its NGC model card warns that depth "may be unreliable" on transparent objects ([NGC](https://catalog.ngc.nvidia.com/orgs/nvidia/tao/models/foundationstereo)). The project page shows good results on the Booster transparent dataset ([project](https://nvlabs.github.io/FoundationStereo)). The two sources conflict, so test it on your own glass.
   - **Fast-FoundationStereo** (CVPR'26) is over 10× faster ([CVPR](https://cvpr.thecvf.com/virtual/2026/poster/38688)). It runs about 8.8 FPS (max_disp 192) to 13.5 FPS (max_disp 64) on Orin at 448×640 with TRT FP16 ([summary of repo benchmark](https://gh.r-mj.com/UniflexAI/Fast-FoundationStereo)). The commercial checkpoint is under the NVIDIA Open Model Agreement ([repo](https://github.com/NVlabs/Fast-FoundationStereo)).
   - Isaac ROS added FoundationStereo in 4.0 and Fast-FoundationStereo in 4.5 ([release notes](https://nvidia-isaac-ros.github.io/releases/index.html)). Those releases require JP 7.x.
4. **Monocular metric depth:**
   - **Depth Anything 3** (Nov 2025). DA3METRIC-LARGE (0.35B) is Apache-2.0 and gives meters as `focal*out/300`. DA3-SMALL/BASE are Apache; the Giant/Large any-view models are CC-BY-NC ([repo](https://github.com/ByteDance-Seed/Depth-Anything-3)).
   - Community work runs DA3-SMALL with TensorRT on Jetson ([ROS 2 wrapper](https://discourse.openrobotics.org/t/depth-anything-3-ros-2-wrapper-development/51030.md)).
   - Mono depth is scale-ambiguous on its own. Use it to fill holes, aligning its scale to the valid D435 pixels around the object.
5. **Newer research to watch (2026):**
   - SeeClear, "generative opacification" ([arXiv 2603.19547](https://arxiv.org/pdf/2603.19547)).
   - StereoAnything, transparent grasping with zero-shot stereo ([IEEE TCYB 2026](https://doi.org/10.1109/tcyb.2026.3670734)).
   - Trans2Occ ([arXiv 2606.01777](https://arxiv.org/pdf/2606.01777)).
   - DeLTa, language-guided manipulation of transparent objects ([arXiv 2510.05662](https://arxiv.org/pdf/2510.05662)).

### 3.3 Detecting transparent objects (2D)

- **Datasets:** Trans10K has more than 10k real images with masks of cups, bottles and glass ([arXiv](https://arxiv.org/pdf/2003.13948)). ClearPose has 350K RGB-D frames of 63 household transparent objects ([arXiv](https://arxiv.org/pdf/2203.03890)).
- **How to use them:** fine-tune YOLOE-26-seg (or YOLO26-seg) on a mix of these plus about 300–1,000 images from your own lab tables (see §4). Classes can be `drinking glass`, `wine glass`, `plastic cup`, `glass bottle`.

## 4. Fine-tuning a closed-vocabulary YOLO on custom classes

- **Auto-labeling:** Autodistill runs a "base model" (Grounding DINO, or Grounded SAM / Florence-2 + SAM 2) over unlabeled images with text prompts, then trains a target YOLO on the result in about a dozen lines ([Roboflow guide](https://roboflow.com/train/grounding-dino-and-yolov8), [autodistill](https://blog.brightcoding.dev/2026/09/30/autodistillautodistill-automate-knowledge-distillation-from-foundation-models)). SAM 3 is a stronger labeler for masks ([Ultralytics SAM 3](https://docs.ultralytics.com/models/sam-3)).
- **Review:** correct the labels in Roboflow or Label Studio before training. Auto-labels of transparent objects are the noisiest part of the data.
- **How many images:** Ultralytics recommends ≥1,500 images per class and ≥10,000 labeled instances per class for best results. Add 0–10% background images. Images should match the deployment conditions ([tips](https://docs.ultralytics.com/yolov5/tutorials/tips_for_best_training_results), [maintainer](https://github.com/ultralytics/yolov5/issues/5464)).
- **Practical shortcut (my estimate, not a cited number):** fine-tuning from pretrained YOLOE or YOLO26 weights works with far fewer images. Start with about 200–500 robot-camera images per new class plus Trans10K/ClearPose glass images, then measure.
- **Training time (estimate):** a few thousand 640² images, 100 epochs, n/s model, on one RTX-class GPU takes about 1–3 hours.
- **Export:** export the engine on the Jetson itself. An engine built on another machine fails to deserialize ([forum](https://forums.developer.nvidia.com/t/the-problem-of-deploying-yolov8-on-jetson-orin-with-jetpack-5-1-1/277287)).

## 6. Hybrid architecture (recommended)

```
 D435i (RGB + depth, + IR pair later)
   │
   ├─► [Jetson, always on, ~30 FPS camera-bound]
   │     YOLOE-26s-seg TRT FP16, baked vocabulary = COCO-80 + ~150–300 household prompts
   │     (drinking glass, plastic cup, mug, bottle, ...) → masks
   │     3D: mask + table-plane geometry (transparent-safe) + median depth on valid pixels
   │     → JSON {label, conf, mask_bbox, xyz_cam, xyz_base, height, depth_source}
   │
   └─► [Off-board RTX GPU over Ethernet/Wi-Fi, on demand: tool `find_object(text)`]
         SAM 3.1 (text → masks)  ─or─  Grounding DINO + SAM 2
         optional: LingBot-Depth refinement on the crop
         optional: VLM verify ("is this a drinking glass on a table? yes/no") —
                   Gemini Robotics-ER 1.6 pointing, or the agent's own LLM on the crop
         later: GraspGen / AnyGrasp on the object point cloud → retarget to Dex3
```

Rules:

- The LLM agent first queries the always-on detections.
- On a miss, or confidence below the threshold, it calls `find_object(text)`, which runs the off-board pass on the latest frame.
- If the miss is common (the same class requested repeatedly), add the class to the baked vocabulary and re-export overnight.
- Every 3D result should report `depth_source` (`sensor`, `plane_fit`, `completed`) so the LLM can tell how far to trust the depth.

**Expected rates.**

- Always-on tier: **estimate** ≥30 FPS for YOLOE-26s-seg on Orin NX. This is based on YOLO26n at 4.13 ms on the same board ([guide](https://docs.ultralytics.com/guides/nvidia-jetson/)) and Ultralytics' claim of "close to closed-set speed". It is not measured, so benchmark it with `yolo benchmark`.
- On-demand tier: about 0.2–1 s round trip (**estimate**). SAM 3 takes 30 ms on an H200 ([paper](https://arxiv.org/html/2511.16719v2)); a consumer RTX will be slower, plus encoding and network time.
- If everything must stay onboard: Grounding DINO at about 7 FPS or SAM 2 base at about 7 FPS on Orin NX in Super mode ([NVIDIA](https://developer.nvidia.com/blog/nvidia-jetpack-6-2-brings-super-mode-to-nvidia-jetson-orin-nano-and-jetson-orin-nx-modules)).

- **Caveat:** Embedl's SAM 3 build is validated only on TRT 10.1/10.3. It gives wrong masks on newer TRT ([HF](https://huggingface.co/embedl/sam3)), which is a concrete risk of moving to JP 7.2's TRT 10.16.

**Should you upgrade from JP 5 to 6?**

- **Not required for steps 1–3 below.** Those steps are YOLOE-26 onboard, plane-fit depth, and an off-board SAM 3 server, and Ultralytics 8.4.198 still targets py3.8 ([PyPI](https://pypi.org/pypi/ultralytics/json)).
- **Worth it once you want any of the following:**
  - onboard ViT models (SAM 2 / EfficientViT-SAM / Grounding DINO via TAO/JPS),
  - Isaac ROS FoundationPose,
  - Super mode,
  - Python 3.10 containers that are no longer pinned to Ubuntu 20.04.
- **Use JP 6.2.x, not 7.2, on the G1 for now.** There is a G1-specific JP 6.2 flashing procedure (remove the NVMe, `dd` the image, flash the QSPI with `flash_nx_module.sh`, then `nvpmodel -m 0`) in NVIDIA's GR00T-WholeBodyControl docs ([guide](https://github.com/NVlabs/GR00T-WholeBodyControl/blob/main/docs/source/references/jetpack6.md)). A community G1 JP 6.2 image also exists ([HF](https://huggingface.co/datasets/wty-yy/unitree_flash/blob/main/README.md)). I found no G1 image for JP 7.2. The Orin NX sits on Unitree's carrier board, and generic Orin NX JP6 flashes have had boot and USB failures ([forum](https://forums.developer.nvidia.com/t/orin-nx-16g-cant-boot-after-update-to-jetpack-6-1/318282)).
- **Protect the current disk:** buy a second NVMe SSD, flash JP 6.2 onto it, and keep the current SSD untouched as the rollback. This preserves other users' files on the robot. Note that the QSPI bootloader flash is shared: after it, the old JP5 SSD may need its own QSPI re-flash to boot again. Confirm with Unitree before you start.

## 8. Step-by-step migration from the current YOLO11n TRT pipeline

1. **Fix 3D first (works with the current detector, JP5).** For `cup`/`wine glass`/`bottle` and any detection whose center depth is 0, or is more than about 3 cm behind the depth ring around the object:
   - Use the table-plane fit plus bottom-contact ray (see §3.2.1). Use the bbox bottom edge until masks exist.
   - Add `depth_source` to the JSON.
   - Cost: one RANSAC per frame on the valid depth around the object.
2. **Swap the detector for YOLOE-26s-seg on JP5:**
   - `pip install ultralytics>=8.4` in the existing py3.8 container.
   - `model = YOLOE("yoloe-26s-seg.pt"); model.set_classes(VOCAB); model.export(format="engine", half=True)`, run **on the Orin**.
   - If TRT 8.5 rejects an op, fall back to `yoloe-11s-seg`, or export ONNX at a lower opset. This is unverified, so plan time for it.
   - Benchmark with `yolo benchmark`. Keep the current YOLO11n engine as a fallback flag.
   - Use mask-median depth on valid pixels instead of the center pixel.
3. **Stand up an off-board "perception server" on an RTX laptop or desktop** (any CUDA ≥12.6 GPU; SAM 3 needs Python ≥3.12 and PyTorch ≥2.7 ([repo](https://github.com/facebookresearch/sam3))):
   - Endpoint `POST /find {jpeg, depth_png, intrinsics, text}` → SAM 3.1 masks.
   - Return 3D results using the same plane-fit and depth logic.
   - Expose it to the LLM as a tool (`find_object`). The Jetson sends one frame per request.
4. **Add VLM verification and pointing as a fallback.** When SAM 3 confidence is low, crop the image and ask the VLM yes/no, or ask Gemini Robotics-ER 1.6 for a point ([docs](https://ai.google.dev/gemini-api/docs/robotics-overview?hl=ko)).
5. **Depth completion:** add LingBot-Depth (Apache-2.0) on the server for transparent or invalid-depth crops. Compare it against plane-fit on 20–50 glass placements, using a tape-measured ground truth.
6. **Fine-tune for your objects:**
   - Auto-label robot-camera footage with SAM 3 / Grounding DINO, then review in Roboflow or Label Studio.
   - Mix in Trans10K and ClearPose glass images.
   - Fine-tune YOLOE-26s-seg, then re-export it on the Jetson.
7. **(Optional) Upgrade to JP 6.2.x on a second SSD:** enable MAXN SUPER, use Python 3.10 containers, and consider onboard EfficientViT-SAM or Isaac ROS FoundationPose.
8. **Grasping:** run GraspGen (or licensed AnyGrasp) on the server against the masked object point cloud, then retarget the parallel-jaw grasp to Dex3 as HERO does ([HERO](https://arxiv.org/pdf/2602.16705)). Try FoundationPose only for objects you own and can scan.
